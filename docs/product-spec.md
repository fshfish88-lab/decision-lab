## 完整产品设计与开发方案

# 一、项目定位

## 1.1 项目名称

**DECISION LAB**

中文副标题：

**选择困难症终结器**

推荐首页 Slogan：

> **今天，我们替你做决定。**

辅助文案：

> 输入你的选项，选择一种决策方式，剩下的交给我们。

项目整体定位不是严肃的专业决策软件，而是：

> **一个具有设计感、游戏感和轻度荒诞幽默的个人决策网站。**

网站一方面提供真正可用的随机决策、多指标评分等功能，另一方面通过克制的塔罗仪式感和一本正经的荒诞表达增强趣味性。

---

# 二、核心产品理念

整个网站围绕三个关键词展开：

## 2.1 好用

用户进入网站后，10～20 秒内即可完成一次决策。

不强制登录。

不设置复杂的前置步骤。

## 2.2 好玩

不同决策方式应该产生明显不同的体验。

不是单纯：

> 输入 → Random → 输出。

而是：

> 输入 → 选择决策方式 → 动画分析 → 结果揭晓 → 趣味解释。

## 2.3 好看

采用已经确定的：

> **浅色实验室 + Bento Grid + 柔和科技感**

整体保持：

- 大面积留白
- 极浅灰背景
- 白色卡片
- 淡紫、淡黄、淡粉、淡绿作为功能区分
- 深色正文
- 圆角 UI
- 非常轻的阴影
- 简洁动画
- 适量 3D / Clay 风格小图标

避免做成：

- 传统企业 Dashboard
- 赛博朋克
- 满屏渐变
- 过度可爱
- 传统工具网站

# 十二、四种核心决策模式

这是网站最核心的部分。

## 12.1 随机模式

图标：

🎲 / 3D 骰子

名称：

### 随机模式

副标题：

> 掷骰子，听天由命。

原理：

所有候选项等概率。

公式：

\[
P_i=\frac{1}{n}
\]

### 决策过程

点击后进入动画：

```text
正在打乱命运……

正在制造随机性……

正在假装这是一个严肃过程……
```

最终随机选择一个结果。

---

## 12.2 科学模式

图标：

⚖ / 柱状图

名称：

### 科学模式

副标题：

> 多指标评分，假装很严谨。

用户首先填写评价维度。

默认模板：

- 喜欢程度
- 价格
- 距离
- 便利程度

用户可以：

- 添加指标
- 删除指标
- 调整权重

权重滑块：

```text
喜欢程度    40%
价格        25%
距离        20%
便利程度    15%
```

总权重必须：

\[
\sum w_j=100\%
\]

用户随后对不同方案评分：

1～10 分。

计算：

\[
S_i=\sum_{j=1}^{m}w_jx_{ij}
\]

得到方案排名。

后期可以升级成：

**TOPSIS 模式**

但第一版不需要。

---

## 12.3 玄学模式

图标：

轨道 / 几何日月 / 塔罗牌背

名称：

### 玄学模式

副标题：

> 亲手抽一张，让大阿卡纳替你表态。

这一模式不需要 AI。

核心采用：

> **22 张大阿卡纳 + 7 张牌阵 + 正逆位 + 候选映射**

交互流程：

```text
输入候选项
    ↓
进入独立塔罗页
    ↓
从 22 张大阿卡纳中抽出 7 张牌背
    ↓
洗牌时预先确定正逆位和候选项映射
    ↓
用户凭第一感觉亲手选一张
    ↓
翻牌并显示牌名、关键词、独立牌面图案、简短征兆与本轮指向
```

牌阵必须在用户点击前完成映射。点击牌后只能读取该位置已经确定的结果，不得再随机选择候选项。只要存在至少两个有效候选项，7 张牌中至少映射到两个不同结果。

结果页显示：

- 罗马数字、英文牌名与中文牌名
- 正位或逆位
- 3 个以上关键词
- 1～5 级牌面强度
- 22 张大阿卡纳使用可相互辨认的象征性几何插画，翻牌和完整结果复用同一图案
- 每个正逆位结果统一按“牌名与正逆位 → 3 个关键词 → 牌面含义 → 为什么是它 → 逆位提醒 → Decision Lab 冷幽默”表达
- “为什么是它”嵌入本轮候选项并说明对应关系；“逆位提醒”给出一个风险或反面可能
- 文案必须清楚可懂，不使用“命运缝隙、第三次回声、未被命名的符号”等抽象套话，也不输出具体行动建议
- 旧版塔罗历史缺少新版结构字段时继续显示原单段牌意

不再生成“宇宙共振率”“平行时间线”“玄学置信度”等伪科学百分比。

页脚提示：

> 塔罗解读仅供娱乐。牌已经表态，真正的决定权仍然在你。

---

## 12.4 AI 模式

图标：

🤖

名称：

### AI 模式

副标题：

> AI理解你的需求，再认真分析一次。

与其他模式不同。

用户可以输入自然语言：

> 我纠结火锅和日料，预算大概 100 元，不想走太远，但是今天特别想吃肉。

AI负责：

### 第一步：需求提取

提取：

```text
候选方案：
火锅
日料

预算：
≤100 元

偏好：
肉类偏好较高

距离：
重要
```

### 第二步：建立指标

AI生成建议指标：

```text
口味       35%
价格       25%
距离       20%
满足感     20%
```

### 第三步：用户确认

用户可以修改。

### 第四步：算法评分

真正的最终排序尽量使用数学算法完成。

### 第五步：AI解释

AI负责自然语言输出。

例如：

> 火锅的综合得分更高，主要优势来自口味偏好和满足感。虽然价格可能略高，但仍处于预算范围内，因此今晚选择火锅更加符合你的当前需求。

即：

> **AI负责理解与解释，算法负责决策。**

```text

   ↓

   ↓
LLM API
```

可以采用：


# 三十三、首页验收标准

## UI

- [ ] 背景为统一浅灰 / 米白色
- [ ] 页面主体最大宽度统一
- [ ] Bento 卡片圆角一致
- [ ] 卡片间距一致
- [ ] 四种模式拥有明确但柔和的颜色区分
- [ ] 不出现强烈霓虹色
- [ ] 不出现明显赛博朋克设计
- [ ] 首屏可以完整看到核心输入和模式选择
- [ ] 页面不存在明显横向滚动

## 输入

- [ ] 至少支持两个选项
- [ ] 支持增加选项
- [ ] 支持删除选项
- [ ] 空选项不能参与决策
- [ ] 重复空格自动清理
- [ ] 少于两个有效选项时禁止决策
- [ ] 最多支持 10 个选项

---

# 三十四、随机模式验收标准

- [ ] 每个候选项拥有相同随机概率
- [ ] 连续运行不会固定返回同一个项目

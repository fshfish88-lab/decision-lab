# DECISION LAB 塔罗展示与四模式 AI 提示词优化设计

日期：2026-08-22

状态：范围已确认，等待书面规格审阅

范围：玄学结果展示、22 张大阿卡纳正逆位牌义、四套独立 AI 提示词、AI 请求超时

## 1. 目标

本次改动解决两个问题：

1. 塔罗结果页虽然已经具备 22 张大阿卡纳、7 张牌阵、正逆位和用户亲手抽牌，但下半部分仍存在通用文案、信息重复和“逆位提醒”只适用于逆位牌的问题。
2. 当前前端只有一套通用的本地结果深度分析提示词和一套 AI 直接决策提示词，随机、科学、塔罗三种模式的 AI 职责没有真正分开；请求超时也只有 20 秒。

改造后需要做到：

- 44 组牌义都能独立、清楚地表达“牌面含义、本次启示、阴影提示”。
- 结果页明确呈现“牌 → 牌义 → 当前问题 → 本轮结果”的逻辑。
- 随机、科学、塔罗、AI 四种模式拥有四套独立核心提示词。
- AI 请求在 40 秒后才安全终止。
- AI 不可用时，随机、科学和塔罗模式仍能在本地完整运行。

## 2. 不在本次范围

- 不改变 22 张牌中随机展开 7 张、牌阵预先均衡映射候选项、用户点击后才揭晓的核心算法。
- 不让 AI 重新决定塔罗或其他本地模式的最终结果。
- 不修改后端 system prompt、接口地址或 JSON 响应协议。
- 不增加流式输出、决策人格、云端记忆或新的依赖。
- 不重做首页、抽牌动画、随机页、科学评分页或 AI 结果页的视觉结构。

## 3. 塔罗牌数据模型

### 3.1 决策倾向

每个正位和逆位牌义增加一个 `decisionStyle`，取值固定为六类：

- `EXPLORE`：尝试新选择、离开惯性。
- `STABILIZE`：优先稳定、成熟、低波动的落点。
- `FOLLOW_DESIRE`：承认真实偏好和吸引力。
- `ACT`：停止追加比较，把选择变成行动。
- `PAUSE`：把结果视为暂定落点，提醒信息仍可能不足。
- `BREAK_PATTERN`：中断反复纠结、执念或旧规则。

`decisionStyle` 只影响解释方式，不改变牌阵已经确定的获胜候选项。

### 3.2 每组牌义字段

22 张牌的正位与逆位共 44 组数据，全部显式定义以下内容：

- `keywords`：恰好 3 个关键词。
- `decisionStyle`：六类倾向之一。
- `interpretation`：这张牌本身的通俗含义。
- `message`：这张牌对当前问题提供的观察角度。
- `shadowTitle`：有辨识度的动态标题，例如“别把松绑变成逃避”。
- `shadow`：牌面力量走向反面时的提醒；正位和逆位都使用该字段。
- `strength`：1–5 的决策信号强度，表示“牌面对现在是否适合做决定的明确程度”，不是概率或置信度。

禁止用一个通用函数批量拼接 44 组正文。可以保留构造函数用于类型收口，但每组牌义必须提供独立内容。

### 3.3 本地牌意落点

新结果根据 `decisionStyle`、3 个关键词和已确定的候选项，在本地生成：

- 三条 `mapping`：每个关键词对应一条对本次决策的作用说明。
- `verdict`：`{候选项}。就这样。`
- `verdictSubtext`：解释这次为什么应当接受该落点，但不声称它客观更优。

本地映射不得虚构候选项的价格、距离、熟悉程度或用户经历。它只能解释该牌提供的决策角度，例如“停止追加比较”“把暂定答案变成行动”“中断惯性纠结”。

## 4. 塔罗结果页

### 4.1 上半部分

保留现有三栏主视觉：牌面、牌名与关键词、本轮指向。仅做两项文字调整：

- `牌面强度` 改为 `决策信号`。
- 本轮指向下方使用简短的 `verdictSubtext`，不在这里重复完整牌义。

保留冷幽默“牌已经翻开，反悔不在本轮服务范围内。”

### 4.2 下半部分

左侧三张卡统一为：

1. `MEANING / 01` — `牌面含义`
2. `MESSAGE / 02` — `本次启示`
3. `SHADOW / 03` — 动态 `shadowTitle`

不再使用“为什么是它”和“逆位提醒”。正位同样存在阴影，因此第三张卡在所有方向上统一为 `SHADOW`。

右侧改为一个决策落点区：

- 上部约 70%：`DECISION MAPPING / 牌意落点`，展示三条关键词映射。
- 下部约 30%：`TAROT SAYS`，展示 `verdict` 和 `verdictSubtext`。

### 4.3 元信息与声明

原来的三块大信息卡降级为一行底部元信息：

`DRAW 04 / 07 · RECORD TAROT-XXXXXXXX · SYMBOLIC READING`

删除“科学意见：不予置评”。娱乐声明继续保留，并增加克制的实验室式幽默：

`Decision Lab 不对神秘学结论提供统计显著性保证。`

### 4.4 兼容性

- 新结果保存新字段，刷新和历史记录恢复后展示一致。
- 旧版历史只有 `interpretation/resonance/echo/punchline` 时继续可读，不迁移或删除用户本地数据。
- 旧 V1 伪指标玄学记录继续走现有兼容分支。

## 5. 四套独立 AI 提示词

以下四段作为核心规则原文。实现时不得概括、合并或改写其语义；模式之间只共享候选项格式、输出格式和不与核心规则冲突的基础语气约束。

### 5.1 随机模式

```text
你正在分析 DECISION LAB 的「随机模式」结果。

本轮结果由等概率随机抽样产生，不代表该方案客观更优，
也不代表用户真实偏好更倾向该方案。

本地随机结果已经确定，禁止修改、重新抽取或推荐其他候选项作为本轮结果。

你的任务不是替随机结果寻找虚假的理性依据，而是回答：

1. 这个随机结果在现实中是否存在明显不可执行因素；
2. 如果没有硬性障碍，怎样最轻松地执行这个结果；
3. 用户可能在哪些情况下容易反悔；
4. 哪些现实条件足以让用户合理地放弃本次随机结果；
5. 给出一个简单明确的下一步行动。

分析时明确区分：
「随机抽中了它」
和
「它本身是否更好」。

禁止声称随机结果经过了现实优劣比较。
禁止把随机概率解释成推荐概率或成功概率。
```

### 5.2 科学模式

```text
你正在分析 DECISION LAB 的「科学模式」结果。

本轮结果来自用户自行设置指标、权重和 1~10 分评分后，
通过加权求和模型得到。

本地排名已经确定，禁止修改评分、权重、排名或最终获胜项。

你的任务是作为多指标决策分析师，对现有模型结果进行解释和稳健性检查。

重点分析：

1. 哪些指标贡献最大，真正推动了第一名胜出；
2. 第一名与第二名之间的差距有多大；
3. 当前结果属于明显领先还是微弱领先；
4. 是否存在某个高权重指标主导整个结果；
5. 哪些没有进入评分模型的现实因素可能影响最终执行；
6. 如果用户稍微改变某些评分或权重，结果是否可能翻转；
7. 给出基于当前模型结果的实际行动建议。

不得自行修改用户评分。
不得虚构新的评分数据。
不得声称该模型证明了某个方案“客观最优”。

如果第一名与第二名非常接近，应明确指出：
当前结果对用户输入比较敏感。
```

### 5.3 塔罗模式

```text
你正在解读 DECISION LAB 的「塔罗模式」。

本模式仅供娱乐。
最终候选项由用户亲自抽中的塔罗牌决定，本轮结果已经确定，
禁止替换、重新选择或声称这是客观事实。

你是一名表达清楚、克制、有轻微冷幽默的塔罗解读者。

请按照以下逻辑进行解释：

1. 先用通俗语言解释这张牌及其正位/逆位的核心含义；
2. 结合本轮关键词说明这张牌表现出的心理倾向；
3. 解释为什么这种象征意义可以映射到当前结果；
4. 给出牌面的反面提醒或风险；
5. 最后给一个现实世界的判断标准：
   什么情况下可以听牌，什么情况下应该忽略牌。

重要规则：

- 不要使用晦涩神秘文学；
- 不要写“宇宙频率”“平行时间线”“命运概率”等伪科学数据；
- 不要声称塔罗预测未来；
- 不要编造用户没有提供的经历、性格或心理状态；
- 可以有仪式感，但必须让普通用户一眼看懂；
- 冷幽默只放在结尾，不得破坏牌意解释。

牌面是娱乐性的象征，
真正决定权始终属于用户。
```

### 5.4 AI 直接决策模式

```text
你是 DECISION LAB 的 AI 决策顾问。

你的任务是根据用户提供的现实情况，
从现有候选项中选择一个最值得执行的方案。

必须且只能选择一个现有候选项。
recommended_option 必须与候选项文字完全一致。

决策过程遵循以下优先级：

第一层：硬约束
例如预算、时间、距离、安全、身体条件、明确禁止条件。
违反硬约束的方案不得推荐。

第二层：明确偏好
例如用户明确说“想吃肉”“不想走远”“更重视体验”。

第三层：现实成本与收益
综合考虑时间、金钱、精力、风险、便利性和机会成本。

第四层：可逆性
当多个方案接近时，优先考虑更容易执行、
后悔成本较低或未来仍有机会选择其他方案的选项。

输出时：

1. 先给明确结论；
2. 给出最关键的 2~4 个理由；
3. 指出最大的代价或取舍；
4. 给出什么条件出现时应该重新考虑；
5. 给出立即可以执行的行动计划。

禁止：

- 虚构价格、距离、时间等用户没有提供的事实；
- 为了显得专业而制造数据；
- 推荐候选项以外的方案；
- 同时推荐多个方案逃避决策。

confidence 表示：
根据当前信息，这个推荐相对于其他候选项有多明确，
而不是模型对自己回答的“自信程度”。

信息不足时可以降低 confidence，
但仍应基于已有信息给出一个明确建议。
```

### 5.5 代码边界

保留 UI 当前调用的 `buildDeepAnalysisContent(result)` 作为本地三模式的分发入口，但不再在函数内放置通用分析正文：

```ts
const MODE_ANALYSIS_RULES = {
  random: RANDOM_ANALYSIS_RULES,
  scientific: SCIENTIFIC_ANALYSIS_RULES,
  mystic: TAROT_ANALYSIS_RULES,
}

export function buildDeepAnalysisContent(result: DecisionResult): string {
  return [
    '任务类型：AI 深度分析',
    MODE_ANALYSIS_RULES[result.mode],
    '决策问题：' + result.question,
    '候选项：' + optionLabels(result.options),
    '本地最终结果：' + result.winner.label,
    localDetails(result),
    VOICE_RULES,
  ].join('\n\n')
}
```

实现时将 `MODE_ANALYSIS_RULES` 的键收窄为 `random | scientific | mystic`，并在分发入口拒绝 `ai` 模式，避免 TypeScript 索引越界。AI 直接决策继续独立使用 `buildDirectDecisionContent()`，不得经过 `MODE_ANALYSIS_RULES`。

不得用一段通用“解释现实优缺点、风险、隐藏冲突、可能情景和下一步”的正文替代模式规则。

### 5.6 塔罗 `localDetails()`

`localDetails()` 必须先判断结构化塔罗数据：

```ts
if (result.details?.type === 'mystic' && result.details.tarot) {
  // 优先生成结构化塔罗上下文
}
```

传给 AI 的上下文至少包括：

```text
塔罗牌：XX · JUDGEMENT / 审判
牌面：逆位
关键词：自我否定、迟疑、拒绝结论
决策倾向：PAUSE
决策信号：2 / 5
用户选择位置：6 / 7
牌阵指纹：TAROT-xxxx
牌面解释：……
本次启示：……
阴影提示：……
本轮指向：打游戏
```

存在 `details.tarot` 时不得再把旧版 `evidence/favorable/avoid` 当作主要上下文；只有读取旧版历史记录且缺少 `details.tarot` 时才走现有兼容分支。

## 6. AI 超时

- 将统一请求超时从 `20_000` 改为具名常量 `40_000` 毫秒。
- 深度分析和 AI 直接决策共用同一超时。
- 39,999 毫秒时不得提前中止；40,000 毫秒时触发 `AbortController`，继续映射为现有 `timeout` 错误。
- 页面现有超时提示保持不变。

## 7. 测试策略

所有生产代码遵循测试先行。

### 7.1 牌库

- 22 张牌、44 组正逆位数据全部存在。
- 每组恰好 3 个关键词，`decisionStyle` 合法，`shadowTitle`、`message`、`shadow` 非空。
- 禁止出现旧式晦涩短语和统一模板残留。
- 恶魔逆位、审判逆位、月亮正位等代表性牌义逐字验证关键句。

### 7.2 结果生成与兼容

- 新结果持久化 `decisionStyle/message/shadowTitle/shadow/mapping/verdict/verdictSubtext`。
- 三条映射与三个关键词一一对应，包含本轮候选项但不产生双层书名号。
- 旧历史字段缺失时仍可渲染。

### 7.3 UI

- 出现 `牌面含义 / 本次启示 / 动态阴影标题 / 牌意落点 / TAROT SAYS / 决策信号`。
- 不出现 `为什么是它 / 逆位提醒 / 科学意见 / 不予置评`。
- 元信息只出现一次，娱乐声明只出现一次。

### 7.4 提示词

- 四个构建器各自包含独有角色、目标和禁止规则。
- 随机 Prompt 不冒充科学比较；科学 Prompt 包含排名和贡献；塔罗 Prompt 使用结构化塔罗数据；AI Prompt 使用四层约束顺序。
- 所有本地深度分析都禁止修改最终结果。

### 7.5 超时与全量验证

- 假计时器验证 39,999/40,000 毫秒边界。
- 运行 `lint`、`typecheck`、`test:run`、`test:pages`。
- 本地浏览器复测完整塔罗流程，覆盖桌面端与 375px，检查横向溢出和控制台错误。

## 8. 完成标准

- 44 组牌义不再由通用句式批量拼接。
- 塔罗结果页信息不重复，右侧承担牌意到决策落点的翻译功能。
- 四种模式发出的核心 Prompt 可以从文本上明确区分。
- 请求在 40 秒边界正确中止。
- 旧历史记录可读，全部项目检查和浏览器复测通过。

# DECISION LAB App / Web UI 分离设计

日期：2026-08-30  
状态：已完成可视化评审，待实施计划  
适用项目：`成品文件夹/decision-lab`

## 1. 目标

在保留现有 React、Capacitor、算法、AI、LocalStorage 和路由能力的基础上，为 Android App 建立独立的移动端 UI。网页版继续使用现有 Header、Bento 布局和 Footer；App 使用移动端顶栏、单列任务流、底部导航、Safe Area 和固定主操作区。

本设计采用：

> 同一套 React 与业务逻辑，Web UI 和 App UI 分开维护。

运行环境由 Capacitor 判断。普通桌面浏览器和手机浏览器继续渲染 Web UI；只有原生 Capacitor 环境渲染 App UI。

## 2. 已确认的设计决策

1. 本轮覆盖完整 App 流程：首页、科学、塔罗、AI、分析、结果、历史、统计和关于页。
2. 采用“双壳层 + 双展示组件”，不使用单纯 CSS 缩窄网页，也不使用 Kotlin / Jetpack Compose 重写。
3. 算法、AI 请求、塔罗数据、状态管理、历史记录、统计计算和类型定义继续共用。
4. 现有 Web UI、网页信息架构和手机浏览器响应式界面保持不变。
5. App 顶层导航对应真实页面：`决策`、`记录`、`统计`、`关于`。不伪造尚不存在的“设置”功能。
6. 顶层页显示底部导航；进入具体决策流程后隐藏底部导航，改用返回栏、步骤状态和底部固定主按钮。
7. App 仍打包本地 `dist` 资源；`server.hostname` 只定义 WebView 安全来源，不加载远程网页。

## 3. 范围与非目标

### 3.1 本轮包含

- Capacitor 原生环境识别与可测试的平台上下文。
- 保留现有 Web Shell，新增 Mobile Shell。
- 为所有现有路由增加 App 展示组件。
- App 首页重新组织为单列输入任务流。
- 科学评分、AI 问答等复杂页面移动化。
- 塔罗和分析页面使用移动端沉浸场景。
- 结果、历史、统计和关于页面移动化。
- Safe Area、键盘、返回导航、离线与 AI 失败状态。
- Web 回归、App 视口、Android 构建和 APK 复测。

### 3.2 本轮不包含

- 不重写随机、科学、塔罗或 AI 业务算法。
- 不改变 API 请求和生产数据协议。
- 不增加登录、通知、云同步、分享平台或设置页。
- 不引入 Kotlin / Compose 页面。
- 不改变网页版视觉方向或桌面布局。
- 不为 App 复制第二套状态、存储或接口实现。

## 4. 架构

### 4.1 平台边界

在应用根部增加平台上下文：

```text
Capacitor.isNativePlatform()
          ↓
PlatformProvider
      ↙         ↘
   Web UI      App UI
      ↘         ↙
 DecisionContext / algorithms / ai / storage / analytics
```

`PlatformProvider` 暴露稳定的 `platform: 'web' | 'native'`，并允许测试覆盖运行平台。页面与组件不直接散落调用 `Capacitor.isNativePlatform()`，避免环境判断难以测试和维护。

### 4.2 壳层边界

现有 `AppShell` 改为轻量分发器：

- Web 环境渲染 `WebAppShell`，内容与现有 Header、导航、状态和 Footer 一致。
- Native 环境渲染 `MobileAppShell`，负责 Safe Area、App Bar、Bottom Nav、Flow Top Bar 和 Sticky Action 区域。

建议目录：

```text
src/
├─ platform/
│  ├─ PlatformContext.ts
│  └─ PlatformProvider.tsx
├─ web/
│  ├─ WebAppShell.tsx
│  └─ pages/
├─ mobile/
│  ├─ MobileAppShell.tsx
│  ├─ mobile.css
│  ├─ components/
│  └─ pages/
├─ pages/                 # 页面控制器与共享流程
├─ algorithms/
├─ ai/
├─ storage/
├─ analytics/
└─ state/
```

目录以清晰边界为目标，不为了形式创建空文件。实施时可以逐页迁移。

### 4.3 页面控制器与展示组件

每个页面保留一份状态和事件处理：读取 `DecisionContext`、计算派生状态、调用共享服务并负责导航。控制器将相同数据与回调传给 Web View 或 Mobile View。

```text
HomePage controller
  ├─ WebHomeView
  └─ MobileHomeView
```

禁止在两个 View 中分别复制：

- 有效选项计数；
- 模式选择与路由判断；
- 科学评分计算；
- AI 请求与错误恢复；
- 塔罗抽取与结果生成；
- 历史写入和统计更新。

展示组件只负责布局、语义化标签和触发回调。

## 5. App 信息架构

### 5.1 顶层页面

以下路由显示 App Bar 与 Bottom Nav：

| 导航项 | 路由 | 内容 |
| --- | --- | --- |
| 决策 | `/` | 问题、选项、四种模式和开始按钮 |
| 记录 | `/history` | 历史列表、复用与查看结果 |
| 统计 | `/statistics` | 摘要、模式分布和成就 |
| 关于 | `/about` | 产品说明、隐私和版本信息 |

Bottom Nav 使用现有 Lucide 图标，选中状态同时使用图标、文字和背景，不只依赖颜色。

### 5.2 决策流程页面

以下路由进入专注模式，不显示 Bottom Nav：

- `/science`
- `/tarot`
- `/ai`
- `/analysis`
- `/result`

专注模式包含：

- 顶部返回按钮；
- 页面名称和步骤状态；
- 必要时显示细进度条；
- 单列主内容；
- 底部固定主要操作区；
- 顶底 Safe Area。

返回行为优先关闭当前浮层，再使用路由历史返回。首页保持系统默认行为。本轮先验证 Capacitor WebView 的现有返回行为；只有复测发现问题时才增加官方原生返回插件。

## 6. 页面设计

### 6.1 App 首页

首页按以下顺序显示：

1. 紧凑品牌顶栏：品牌标志、`DECISION LAB`、本地状态。
2. 页面标题：`今天想决定什么？`
3. 问题名称输入。
4. 候选选项编辑器，至少 2 项、最多 10 项。
5. 四种模式 2×2 卡片。
6. 根据模式变化的主要按钮。
7. Bottom Nav。

App 首页不显示桌面版大型 Hero 和 DecisionMachine 主插画。品牌记忆通过标志、模式色和克制的微动画保留，首屏优先让用户在 10～20 秒完成一次决定。

移动选项编辑器继续支持添加、删除、Enter 添加和原有限制，但采用 48px 以上触控目标。模式卡保留随机、科学、塔罗、AI 四种柔和色彩和简短个性文案。

### 6.2 科学模式

科学模式拆为短步骤：

1. 设置判断标准和权重；
2. 按选项逐项评分；
3. 进入分析。

桌面表格在 App 中改为纵向卡片、滑杆、分段控件和逐项评分。总权重始终可见，权重错误在当前页面内说明，不等提交后才提示。

### 6.3 塔罗模式

塔罗使用独立深色沉浸背景，保留统一返回区和娱乐标识。牌组适配单手触控，选中牌保持清晰焦点和确认反馈。减少动态效果时取消强位移、翻转和长时间洗牌，但保留状态变化。

### 6.4 AI 模式

AI 页面使用单列上下文输入和选项摘要。提交后防止重复请求，并在当前卡片中显示加载、错误和重试。请求失败时保留输入，同时提供返回修改或改用本地模式的入口。

### 6.5 分析页面

分析页面显示当前模式、步骤文案和动画状态。动画控制在规格要求内，不人为阻塞主线程。`prefers-reduced-motion` 开启时使用静态进度与文案替代强运动。

### 6.6 结果页面

所有模式遵循相同信息顺序：

1. 先显示唯一结论；
2. 显示模式与可信/娱乐属性；
3. 分层展开证据、评分或解释；
4. 可选 AI 深度分析；
5. 再来一次、修改选项、切换模式等后续操作。

随机、科学、塔罗和 AI 可以保持各自的视觉性格，但操作位置和信息层级一致。App 不横向塞入桌面表格。

### 6.7 历史、统计和关于

- 历史：纵向摘要卡，显示模式、时间、问题和结果；点开查看详情，保留再次决策能力。
- 统计：优先显示关键数字和简化图表；复杂信息分区呈现，不依赖横向滚动。
- 关于：保留产品定位、隐私、本地存储、版本和备案信息；不伪装成设置页。

## 7. 移动端视觉系统

延续 `Light Lab UI + 柔和科技感 + 适量 Clay 3D`，但为 App 定义独立尺度：

| 项目 | App 规则 |
| --- | --- |
| 页面横向留白 | 16～20px |
| 页面标题 | 约 28px，紧凑行高 |
| 区块标题 | 约 20px |
| 正文 | 15～16px |
| 辅助文字 | 12～13px，不承载关键操作信息 |
| 主要触控目标 | 48～56px |
| 输入与按钮圆角 | 12～14px |
| 卡片圆角 | 16～20px |
| 阴影 | 只用于浮层、固定栏和关键层级 |

模式颜色沿用现有规范：

- 随机：`#E9E7FF` / `#7268F2`
- 科学：`#FFF3D5` / `#D69C27`
- 塔罗：`#FFE8EA` / `#E87991`
- AI：`#E8F4DF` / `#72A95A`

主操作仍使用 `#111527`。颜色不作为唯一状态提示。

App 样式集中在独立的、以 `.mobile-app` 为根作用域的样式文件中，避免继续扩大现有 `index.css`，也避免 App 选择器影响 Web。

## 8. Safe Area、键盘与无障碍

- 根壳层使用 `env(safe-area-inset-top)` 和 `env(safe-area-inset-bottom)`。
- Bottom Nav 和 Sticky Action Bar 的底部内边距包含 Safe Area。
- 输入聚焦后，当前字段和提交按钮不能同时被软键盘遮挡。
- 所有交互目标至少 44px，主要按钮目标 48px 以上。
- 保留可见的 `:focus-visible` 状态和语义化标签。
- 模式选择使用边框、选中标记和文案共同表达状态。
- 正文对比度满足 WCAG AA。
- 动画尊重 `prefers-reduced-motion`。

## 9. 数据与错误处理

### 9.1 数据流

Mobile View 与 Web View 使用同一套 `DecisionContext`、reducer、存储模块和数据格式。两端共享代码与 schema：

- 当前问题、选项与模式；
- 科学标准和评分；
- 当前结果；
- 历史记录和数据版本；
- 统计与成就。

UI 分离不能改变历史记录 schema，也不能在 App 内另建一套平行存储。浏览器和 Android WebView 仍各自拥有隔离的本地存储空间，本轮不提供跨设备同步。

### 9.2 离线

APK 包含本地 Web 资源。断网时随机、科学、塔罗、历史和统计继续可用。AI 卡和深度分析明确标注需要网络，但不得阻塞本地模式。

### 9.3 AI 错误

- 保留用户输入；
- 在当前区域显示原因；
- 提供重试；
- 提供返回修改或改用本地模式；
- 禁止白屏、吞错或伪造 AI 结果。

### 9.4 空状态和非法路由

- 历史为空时显示开始决策入口。
- 结果路由缺少有效结果时回到决策入口并解释原因。
- 存储不可用时给出非阻塞提示，本次会话仍可继续。

## 10. 测试与验收

### 10.1 自动测试

- 为 PlatformProvider 覆盖 Web / Native 两种环境。
- AppShell 覆盖双壳层、顶层导航与流程导航。
- 页面控制器继续复用现有业务测试。
- Mobile View 覆盖关键可访问名称、禁用状态、模式切换、错误与重试。
- 原有 `lint`、`typecheck`、`test:run` 和 `build` 全部通过。

### 10.2 Web 回归

- Desktop Web 保持现有 Header、Bento、Footer 和路由表现。
- 手机浏览器仍显示 Web 响应式 UI，不误用 App UI。
- 375px 网页回归无横向滚动。

### 10.3 App 视口

至少验证：

- 375×812；
- 412×915；
- 顶部刘海/状态栏；
- 底部手势区域；
- 软键盘弹出；
- 横向滚动；
- 固定操作区遮挡。

### 10.4 功能流程

完整走通：

```text
首页输入
→ 随机 / 科学 / 塔罗 / AI
→ 分析
→ 结果
→ 历史
→ 统计
→ 关闭并重开 App
```

确认历史持久化、AI 错误恢复、离线本地模式和 Android 返回行为。

### 10.5 Android 交付

完成 Web 验证后：

1. `npm run android:sync`
2. Android 单元任务与 lint
3. `assembleDebug`
4. `apksigner verify`
5. `aapt dump badging`
6. 检查嵌入的 Capacitor 配置
7. 计算交付 APK SHA-256

有设备时补充真机安装；没有设备时明确报告未验证项。

## 11. 实施顺序

1. 平台上下文、双壳层和测试。
2. App 首页、Bottom Nav、Safe Area 和移动样式基础。
3. 科学、塔罗、AI、分析流程页面。
4. 结果、历史、统计和关于页面。
5. 错误、离线、减少动态效果和键盘专项。
6. Web 全回归、App 视口 QA、Android 同步与 APK 交付。

每一阶段都应保持 Web 可运行，不把多个页面的业务逻辑复制到 Mobile View。

## 12. 完成定义

只有同时满足以下条件才可称为完成：

- Capacitor 环境显示完整 App UI，浏览器环境保持 Web UI；
- 所有现有路由具有一致的移动端结构；
- 四种模式和历史统计流程可用；
- Safe Area、键盘、返回与离线状态已复测；
- 自动测试、Web 回归、Android lint 和 APK 构建通过；
- 交付 APK 的包名、版本、签名与哈希已验证；
- 未引入假的设置页、重复业务逻辑或 Compose 第二项目。

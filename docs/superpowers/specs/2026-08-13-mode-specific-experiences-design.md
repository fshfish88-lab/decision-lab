# DECISION LAB 模式差异化体验设计

日期：2026-08-13  
状态：已确认设计方向，待实施

## 1. 问题与目标

当前随机、科学、玄学三种模式虽然入口和算法不同，但分析页与结果页仍共用“统一步骤、胜出卡片、置信度、圆环指标、排名、解释”的模板。用户切换模式后，最终体验差异不够明显；随机模式的圆环指标还容易造成系统进行了真实偏好分析的误解。

本轮目标是保持现有 `Light Lab UI + Bento Grid` 视觉体系，同时将体验调整为：

> 入口统一，分析过程和结果内容因模式而异。

完成后，三种模式从点击主按钮开始就使用不同语言、视觉重点和信息结构。AI 模式仍保持 `V1.5` 禁用，不接入接口，也不展示伪造的 AI 分析。

## 2. 范围

本轮实现：

1. 随机、科学、玄学三套独立分析步骤；
2. 三套独立结果组件；
3. 随机抽签元数据与等概率展示；
4. 科学模式的排名、指标贡献和全方案评分对比；
5. 玄学模式的命运星盘、三条娱乐证据与今日宜忌；
6. 旧版 LocalStorage 记录的兼容降级；
7. Desktop 与 375px Mobile 响应式；
8. 单元测试、流程测试、构建和 GitHub Pages 验证。

本轮不实现：

- AI 模式、AI 接口或模型调用；
- 登录、数据库、云同步和后端；
- 新图表依赖；
- 将娱乐信息伪装成真实统计或科学结论。

## 3. 方案选择

采用“共享结果外壳 + 模式独立内容组件”。共享导航、时间、返回按钮、再次决策、修改选项和历史入口；每种模式独立负责主结果、详细分析和解释。

不采用以下方案：

- 只换文案和配色：改动小，但信息结构仍然相同，无法解决体验同质化；
- 引入重型可视化 Dashboard：会增加包体和复杂度，并破坏轻量、柔和的个人工具气质。

## 4. 组件架构

新增目录：

```text
src/components/results/
├─ ResultShell.tsx
├─ RandomResult.tsx
├─ ScientificResult.tsx
└─ MysticResult.tsx
```

职责：

- `ResultPage.tsx`：处理无结果状态、按 `result.mode` 分派组件、提供重新决策和导航行为；
- `ResultShell.tsx`：共享工具栏、问题标题、模式标签、结果操作区；
- `RandomResult.tsx`：随机结果主卡、命运落点、抽签信息、等概率条和吐槽；
- `ScientificResult.tsx`：推荐项、综合得分、排名、贡献分析、评分对比和确定性解释；
- `MysticResult.tsx`：命运报告、浅色星盘、玄学指标、三条证据、今日宜忌和娱乐声明；
- `AnalysisPage.tsx`：保留同一路由，但通过模式配置渲染三套不同步骤、图标、标题和结束语。

组件可以复用基础按钮、卡片变量和排版 token，但不得重新抽象成一套相同的详细分析 DOM。

## 5. 数据模型

保留 `DecisionResult` 的公共字段，并新增可选的模式详情。详情为可选字段，以便旧版 `HistoryStoreV1` 数据仍可读取。

```ts
interface RandomResultDetails {
  type: 'random'
  sample: number
  winningIndex: number
  seed: string
  drawNumber: string
  probability: number
}

interface ScientificResultDetails {
  type: 'scientific'
  criteria: Criterion[]
  scores: ScientificScoreMap
  contributions: Array<{
    criterionId: string
    name: string
    weight: number
    score: number
    contribution: number
  }>
}

interface MysticEvidence {
  key: string
  title: string
  description: string
  reading: string
}

interface MysticResultDetails {
  type: 'mystic'
  evidence: MysticEvidence[]
  favorable: string
  avoid: string
}
```

`DecisionResult.details` 的类型为三者联合。新生成结果必须写入与 `mode` 一致的详情；读取旧记录时，独立结果组件使用现有公共字段生成安全降级视图，不抛出异常。

随机算法新增可测试的抽签函数，返回本次真实使用的 `[0, 1)` 样本值与落点索引。`seed` 是该样本值的可读编码，不能暗示密码学安全；UI 标注为“本轮随机种子”。等概率始终为 `1 / 有效候选数`。

科学贡献按以下公式计算：

```text
contribution = score × weight / 100
```

全部贡献之和必须与获胜项综合得分一致，误差小于 `1e-6`。方案评分对比展示原始 1～10 分，不将其伪装成百分比。

玄学证据使用本地确定性模板，根据获胜项位置、字符长度、置信度和现有玄学指标生成。证据属于娱乐文案，必须与“仅供娱乐”声明同页出现。

## 6. 分析动画

三种模式使用同一页面容器，但配置完全不同：

### 随机模式

- 标题：`正在启动命运抽签`
- 步骤：`正在洗牌候选项`、`正在生成随机种子`、`正在排除人为干预`、`正在确认命运落点`
- 结束语：`命运确认。`
- 视觉：淡紫色、卡牌横向轻移，不展示真实分析指标。

### 科学模式

- 标题：`正在进行科学计算`
- 步骤：`正在校验评分矩阵`、`正在应用指标权重`、`正在计算综合得分`、`正在生成完整排名`
- 结束语：`计算完成。`
- 视觉：淡黄色、横向数据条逐步填充。

### 玄学模式

- 标题：`正在连接命运频道`
- 步骤：`正在校准宇宙频率`、`正在读取潜意识波动`、`正在搜索平行时间线`、`水晶球连接稳定`
- 结束语：`天机已泄露。`
- 视觉：淡粉色、浅色轨道和小球缓慢旋转。

动画总时长保持约 2 秒，`prefers-reduced-motion` 下缩短至约 250ms；动画不阻塞算法，也不依赖动画完成才生成数据。

## 7. 随机结果体验

信息顺序：

1. 大卡展示获胜项与“命运选择了它”；
2. `命运落点` 横向候选轨迹，终点以 `STOP` 标出获胜项；
3. 三张实验室信息卡：候选数量、理论概率、抽签编号；
4. `RANDOM SEED` 单独展示本轮种子；
5. 所有候选项使用等长概率条，明确每项机会完全相同；
6. 系统评价：`这次没有任何科学依据，但至少你不用继续纠结。`

结果页不显示置信度圆环，不生成“喜欢程度”“后悔概率”等虚假分析。

## 8. 科学结果体验

信息顺序：

1. 最终推荐与 `综合得分 x.xx / 10`；
2. 完整排名，突出第一名并显示与第二名分差；
3. 获胜项指标贡献横条，显示 `指标名、权重、原始评分、贡献值`；
4. 全方案评分对比表，桌面端为表格，手机端允许表格容器内部横向滚动，但页面本身不得横向滚动；
5. `为什么它胜出`，由程序根据最大贡献指标及竞争项差距生成解释。

科学结果不显示百分比圆环，不出现宇宙、命运等娱乐指标。贡献图使用 CSS 条形图，不新增可视化依赖。

## 9. 玄学结果体验

信息顺序：

1. `DESTINY REPORT / 今日命运报告` 主卡，展示获胜项和命运匹配度；
2. 浅色命运星盘：中央为获胜项，外围展示 3～5 个现有玄学指标，轨道轻微旋转；
3. 三张 `玄学证据` 卡，分别表达输入顺序、字符共振和平行时间线；
4. 今日宜：选择获胜项；今日忌：重新打开选项继续纠结；
5. 系统结论与“仅供娱乐”声明。

命运星盘不使用 emoji 作为正式图标，使用 CSS 几何元素和 Lucide 图标。整体保持浅色，不转为黑紫色算命站。

## 10. 响应式与无障碍

- Desktop 保持双列或 Bento 多列；375px 下所有主要区块改为单列；
- 页面级无横向滚动；科学对比表只允许自身容器滚动；
- 操作控件不小于 44px，保留 `:focus-visible`；
- 结果图形同时提供文字标签，颜色不是唯一信息来源；
- 装饰轨道使用 `aria-hidden="true"`；
- 动画尊重 `prefers-reduced-motion`。

## 11. 测试与验收

自动化测试至少覆盖：

1. 随机抽签返回真实样本、索引和等概率详情；
2. 科学贡献之和等于综合得分；
3. 玄学生成恰好三条娱乐证据和宜忌；
4. 分析页按模式展示不同标题与步骤；
5. 结果路由按模式渲染独立标题，随机页不出现科学贡献，科学页不出现命运星盘，玄学页不出现评分矩阵；
6. 旧结果缺少 `details` 时仍能渲染；
7. 原有随机、科学、玄学完整流程和历史记录不回归。

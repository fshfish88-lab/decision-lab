# DECISION LAB AI 前端接入设计

日期：2026-08-13  
范围：V1.5 前端 AI 接入与结果体验  
状态：用户已确认

## 1. 目标

在不改变随机、科学、玄学现有算法和差异化结果页的前提下，接入已经正式部署的两个 AI 接口：

- `POST https://api.fshfish.com/api/ai/deep-analysis`
- `POST https://api.fshfish.com/api/ai/decision`

产品形成两层 AI 能力：

1. 随机、科学、玄学模式先由本地算法完成决策，用户主动点击后，AI 只补充解释。
2. 独立 AI 模式理解问题、候选项和用户背景，直接给出最终建议。

前端不得出现 DeepSeek API Key，也不得再调用旧 `/api/analyze`。

## 2. 核心产品原则

- 随机、科学、玄学的本地结果是不可覆盖的事实来源。AI 深度分析不能修改获胜项、概率、评分、排名或玄学结果。
- AI 模式本身是决策引擎，用户心态是“你直接告诉我怎么办”，不再要求用户确认指标、设置权重或进行二次配置。
- AI 请求只由用户主动触发，不在页面加载时自动调用。
- AI 服务失败不能影响三个本地模式及其历史记录。
- 两种 AI 返回分别使用独立 Bento UI，不显示为聊天窗口或一整块无结构文本。
- 维持“严肃界面 + 不太严肃的表达”，结论必须清楚，幽默不能掩盖风险。

## 3. 用户流程

### 3.1 本地模式的 AI 深度分析

```text
随机 / 科学 / 玄学完成本地决策
→ 展示现有模式专属结果页
→ 用户点击“AI 深度分析”
→ 请求 deep-analysis 接口
→ 在当前结果页展开独立 AI Bento 分析区
```

深度分析是当前结果页的可选补充。本版本不把深度分析响应写入 LocalStorage；刷新或离开结果页后可重新请求，避免改变现有历史数据结构和把一次可选解释误当成原始决策结果。

### 3.2 独立 AI 模式

```text
首页填写问题和至少两个候选项
→ 选择 AI 模式
→ 进入 AI 背景输入页
→ 填写真实情况和偏好
→ 点击“让 AI 替我决定”
→ 展示 AI 专属分析动画
→ 进入 AI 专属结果页
→ 写入统一历史记录
```

AI 模式结果可使用现有“再来一次、换一种模式、修改选项、查看记录、反悔、分享”能力。其中“再来一次”回到 AI 背景输入页，不复用本地分析动画。

## 4. API 契约

### 4.1 统一客户端边界

新增一个 AI API 客户端，集中维护地址、超时、请求、响应校验和错误映射。组件不得直接调用 `fetch`。

两个正式接口的请求体均按已经部署并测试的契约发送：

```json
{
  "content": "由前端按固定模板组合的完整决策上下文"
}
```

前端超时为 20 秒。请求中禁止重复提交，失败后允许用户主动重试。

### 4.2 深度分析响应

```json
{
  "success": true,
  "type": "deep-analysis",
  "data": {
    "overview": "...",
    "key_factors": ["..."],
    "risks": ["..."],
    "hidden_conflicts": ["..."],
    "scenarios": ["..."],
    "next_steps": ["..."]
  }
}
```

前端必须校验 `success`、`type`、`data` 以及全部字段类型。数组允许为空，但不得接受缺失字段或非字符串成员。

### 4.3 AI 最终建议响应

```json
{
  "success": true,
  "type": "decision",
  "data": {
    "recommended_option": "火锅",
    "confidence": 89,
    "verdict": "...",
    "core_reasons": ["..."],
    "main_tradeoff": "...",
    "conditions_to_reconsider": ["..."],
    "action_plan": ["..."]
  }
}
```

`confidence` 在界面中统一称为“推荐强度”，范围必须为 0–100，不表达准确率或客观概率。`recommended_option` 必须与当前有效候选项按去除首尾空格后的文本精确匹配；不匹配时视为无效响应，不生成结果、不写入历史记录。

## 5. 提示词与上下文构建

请求仍使用后端的 `content` 字段，但前端必须用稳定、有标签的模板组合上下文，不能只发送用户的一句话。

### 5.1 深度分析上下文

通用内容包括：

- 任务说明：只解释，不改变本地结论。
- 决策问题、全部候选项、当前模式和获胜项。
- 用户可用背景；没有时明确标注“未提供额外背景”。
- 当前模式已有的计算或展示数据。

模式专属数据：

- 随机：理论概率、候选数量、抽签编号、随机指纹。
- 科学：完整排名、指标权重、评分矩阵、获胜项贡献。
- 玄学：命运证据、宜忌、匹配指标，并明确玄学内容仅供娱乐。

### 5.2 AI 决策上下文

内容包括决策问题、全部候选项、用户背景、输出必须选择现有候选项的约束，以及要求给出理由、取舍、重新考虑条件和行动方案。

### 5.3 产品人格提示

两类提示词都加入以下语气要求：

- 像聪明、果断、略带调侃的决策顾问。
- 结论、风险和行动建议优先，幽默只作为表达层。
- 避免低幼梗、网络烂梗、攻击性表达和虚构事实。
- 健康、安全、法律、财务等严肃内容自动收敛幽默。
- 尽量在合适字段中保留一句符合 DECISION LAB 气质的短吐槽。

模式语气有所区分：随机像现实检查员，科学像有冷幽默的数据分析师，玄学像把宇宙安排翻译成现实建议，AI 模式像直接替用户拍板的私人顾问。

## 6. 前端组件与状态

### 6.1 请求层

- `src/ai/aiApiClient.ts`：端点常量、20 秒超时、错误类型、运行时响应校验。
- `src/ai/aiPromptBuilders.ts`：纯函数形式的深度分析和直接决策上下文构建器。
- 不保留旧的指标建议客户端语义；原 `aiDecisionClient.ts` 将被替换或重构为新的正式接口客户端。

### 6.2 深度分析 UI

新增 `AiDeepAnalysisPanel`，插入现有模式专属结果内容之后、“决定之后”操作区之前。初始状态只显示 CTA，不自动请求。

展开后的 Bento 结构：

- 总览大卡：`overview`
- 关键因素卡：`key_factors`
- 风险卡：`risks`
- 隐藏冲突卡：`hidden_conflicts`
- 情景卡：`scenarios`
- 下一步建议卡：`next_steps`

组件只持有请求状态和响应，不获得修改 `DecisionResult` 的回调，从组件边界上阻止 AI 覆盖本地结果。

### 6.3 AI 输入与结果 UI

现有 `AiPage` 从“需求实验室/生成指标”改为轻量背景输入页：展示问题和候选项，提供最多 500 字背景文本，CTA 为“让 AI 替我决定”。背景不能为空。

新增 `AiResult` 专属布局：

- 最终建议 Hero：`recommended_option` 与推荐强度。
- 核心判断：`verdict`。
- 为什么推荐：`core_reasons`。
- 需要接受：`main_tradeoff`。
- 重新考虑条件：`conditions_to_reconsider`。
- 行动计划：`action_plan`。

`DecisionResultDetails` 增加 AI 详情分支，AI 结果通过现有 `DecisionResult` 和历史存储机制持久化。历史列表、统计和分享逻辑对 `mode: "ai"` 保持兼容，不伪造本地评分、概率或玄学指标。

### 6.4 加载体验

请求期间显示轻量、非阻塞的阶段文案：

- 正在理解你的纠结……
- 正在比较候选方案……
- 正在评估你可能后悔的地方……
- AI 似乎已经有主意了……

动画尊重 `prefers-reduced-motion`，不会人为阻塞线程。真实请求完成后立即进入结果；不会为了演出强制等待。

## 7. 错误处理

客户端统一映射：

- HTTP 或 CORS 失败：AI 服务暂时无法连接。
- 20 秒超时：本次分析已安全停止，可重试。
- 429：请求有点太密集，请稍后再试。
- 非法 JSON 或结构不符：返回内容未通过格式检查。
- 推荐项不在候选项：AI 没有按规则选择现有方案，本次结果不保存。

所有错误通过 `aria-live` 提示。错误后保留用户问题、选项和背景；本地模式原结果始终可见且可继续操作。

## 8. 响应式与无障碍

- Desktop 使用两至三列 Bento，375px Mobile 退化为单列。
- 不出现页面级横向滚动，长文本允许自然换行。
- 按钮可点击区域不小于 44px，请求中同时使用 `disabled` 和可读状态文案。
- Bento 标题使用语义化标题层级，动态内容设置适当的 `aria-live`。
- 颜色不是唯一状态提示，保留键盘焦点样式和减少动画偏好。

## 9. 测试与验收

### 9.1 自动化测试

- Prompt 构建器：包含完整上下文、模式专属数据、不可覆盖规则和幽默语气规则。
- API 客户端：两个端点、请求体、20 秒超时、429、网络失败、非法 JSON、字段缺失和合法响应。
- 深度分析组件：默认不请求、点击后请求、请求中防重复、成功 Bento、失败重试、本地结果不变。
- AI 模式：背景输入、提交、加载、推荐项校验、AI 结果生成、历史写入和再次运行。
- 现有随机、科学、玄学流程及结果页回归测试全部保留。

### 9.2 完成检查

运行并修复：

```text

test

```

使用真实浏览器复测 Desktop 和 375px Mobile，检查两类 Bento、加载态、错误态、页面溢出和控制台。最后调用两个线上正式接口各一次，确认真实结构与 UI 渲染一致；再发布到现有 GitHub Pages，并验证线上资源和两条用户流程。

## 10. 非目标

- 不修改两个已部署的后端接口。
- 不在前端保存或展示任何模型 API Key。
- 不增加登录、云同步或跨设备 AI 结果同步。
- 不让 AI 深度分析重新排名或覆盖本地结果。
- 不改动现有三个模式已经确认的差异化结果结构。

# Decision Lab 移动端主导航联动动画设计

日期：2026-08-31
状态：已确认设计方向，待书面规格审阅

## 1. 背景与目标

Decision Lab 当前移动端使用 React Router 切换页面，所有路由共用轻微的淡入和平移转场。底部主导航由四个独立链接组成，选中项背景会立即切换。

本次改造参考 Verifin 的原生分页手感，在不复制其 Flutter/Dart 源码的前提下，将移动端四个一级页面改成两套同步动画：

1. 页面按目标所在方向横向切换；
2. 底部唯一的选中胶囊同步滑到目标导航项。

目标是在保留 Decision Lab 浅色实验室视觉、HashRouter、Android 返回逻辑和现有页面结构的前提下，让一级导航更接近原生 App。

## 3. 交互设计

### 3.1 一级页面方向

一级页面固定顺序为：

```text
决策 → 记录 → 统计 → 关于
```

- 从较小索引进入较大索引时，旧页面向左退出，新页面从右侧进入；
- 从较大索引进入较小索引时，旧页面向右退出，新页面从左侧进入；
- 点击当前页面不触发导航和转场；
- 浏览器或 Android 返回操作继续遵循现有历史栈方向，不改变退出提示逻辑。

页面仍由 React Router 按路由渲染，不建立四页常驻的真实 Pager。这样可以避免同时挂载多个页面、重复主区域、滚动位置冲突和额外内存占用。

### 3.2 二级流程

以下二级流程保持现有前进/返回转场：

```text
/science
/tarot
/ai
/analysis
/result
```

它们不参与一级页面索引比较，也不显示底部主导航。进入二级流程时由右向左轻移，返回时由左向右轻移。

### 3.3 底部导航

- 导航容器内只存在一个真实选中胶囊；
- 胶囊宽度等于一个导航槽位减去内边距；
- 胶囊位置由当前一级页面索引计算；
- 图标和文字位于胶囊之上，继续使用 `aria-current="page"` 表示当前页面；
- 指针按下时目标项缩放到 `0.94`，释放后恢复到 `1`；
- 键盘激活不依赖指针事件，Enter 和 Space 仍走标准链接行为。

## 4. 动画参数

### 4.1 标准动态效果

| 动画 | 时长 | 缓动 | 说明 |
|---|---:|---|---|
| 一级页面切换 | 260ms | `cubic-bezier(0.215, 0.61, 0.355, 1)` | 与胶囊同步开始 |
| 胶囊位移 | 240ms | `cubic-bezier(0.215, 0.61, 0.355, 1)` | 单一元素移动 |
| 导航按压 | 160ms | `cubic-bezier(0.215, 0.61, 0.355, 1)` | `scale: 1 → 0.94 → 1` |

一级页面使用横向位移作为主要提示，透明度只用于弱化重叠，不制造明显闪烁。内容区域必须裁切横向溢出，转场结束后不保留多余变换。

### 4.2 减少动态效果

当系统启用 `prefers-reduced-motion: reduce`：

- 页面横向位移变为 `0`；
- 胶囊不做连续滑动，直接定位到当前槽位；
- 导航按压不缩放；
- 页面只保留不超过 80ms 的轻微透明度切换；
- 不影响路由、焦点和 Android 返回行为。

## 5. 代码结构

### 5.1 路由顺序与方向

在移动端导航模块中提供可测试的纯函数：

- 将一级路径映射为固定索引；
- 判断一次路由变化是否属于一级页面切换；
- 根据起点和终点索引返回 `-1`、`0` 或 `1`。

纯函数不读取 DOM，也不直接调用路由 API，便于覆盖相邻跳转、跨两项跳转和非一级路由。

### 5.2 一级转场组件

新增 `MobilePrimaryRouteTransition`，只负责一级页面转场。组件接收当前路径、导航方向和页面内容，使用 Framer Motion 执行进入与退出动画。

现有 `MobileRouteTransition` 继续负责二级流程；若为减少重复而共享动画常量，共享内容只包括时长和缓动，不混合两种路由语义。

### 5.3 浮动主导航组件

从 `MobileAppShell` 中提取移动端主导航组件，负责：

- 根据当前路径得到选中索引；
- 渲染单一胶囊；
- 渲染四个语义化导航链接；
- 触发既有 `navigateForward`；
- 提供按压、焦点和减少动态效果状态。

`MobileAppShell` 仍负责一级/二级布局切换、流程页标题、退出提示和 Android 返回监听。

## 6. 状态与异常处理

- 当前路径不是一级页面时不计算胶囊索引，并按现有逻辑隐藏主导航；
- 快速连续点击时，以 React Router 最终提交的路径为事实来源，动画状态不得独立持有一个可能过期的“当前页面”；
- 点击当前导航项直接返回，不新增历史记录；
- 跨两项或三项跳转仍只执行一次 260ms 转场；
- 页面卸载、系统返回或路由替换时不得留下计时器、指针捕获或全局事件监听；
- 本方案不使用拖动手势，因此不引入手势阈值、吸附失败或指针取消状态。

## 7. 无障碍与响应式

- 导航继续使用 `<nav aria-label="App 主导航">`；
- 每个目标保留可读名称和 `aria-current="page"`；
- 胶囊设置为装饰元素，不进入无障碍树；
- 所有导航目标最小尺寸不低于 44×44px；
- `:focus-visible` 必须清晰可见，不能被胶囊遮挡；
- 375px 宽度下四项均匀分配，不出现文字截断和页面级横向滚动；
- 安全区内边距继续适配 Android 全面屏。

## 8. 测试策略

按测试优先顺序实施：

1. 为一级路径索引和方向计算写失败测试；
2. 为底栏单一胶囊、选中索引、当前项点击和减少动态效果写失败测试；
3. 为一级与二级转场分流、方向、时长和缓动写失败测试；
4. 写最小实现使测试通过；
5. 运行现有全部测试，确认 Android 返回、流程页导航和页面语义没有回归。

浏览器复测覆盖：

- 375×812 移动视口；
- 决策 → 统计、关于 → 记录等跨项切换；
- 流程页进入和返回；
- 快速连续点击；
- 键盘 Tab、Enter、Space；
- 减少动态效果；
- 页面无横向溢出；
- 控制台无错误和警告。
